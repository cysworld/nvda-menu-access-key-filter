Menu Access Key Filter

A prototype for NVDA issue #20912.

What it does

Menus in Chinese, Japanese and Korean applications often expose a character taken from the item's own label as its access key. NVDA then reads that character again after the label, for example:

  • Internet Download Manager: 任务 子菜单 Alt+任
  • Bookworm: 打开... Ctrl+O 打

A menu access key has to be typed with one key press, and Han, kana and hangul characters can only be entered through an IME. This add-on removes such unusable access keys from menu items, menus and popup menus. After installing it, the examples above are read as 任务 子菜单 and 打开... Ctrl+O.

What it keeps

  • Accelerators such as Ctrl+O.
  • Latin access keys, including ones that also appear in the label (the t and a in the NVDA menu), and the Latin letters in parentheses that Chinese, Japanese and Korean menus use, such as 文件(&F).
  • Access keys written in scripts that can be typed directly on a keyboard layout, such as Cyrillic, Greek, Arabic, Hebrew, Thai and Devanagari.

Only a shortcut made of a single character from an IME-only script, optionally preceded by modifiers (打, Alt+任), is removed.

Where it applies

The filter changes NVDA's keyboardShortcut property of menu related objects, so it applies to speech, braille and the command that reports the shortcut key of the current object (NVDA+Ctrl+Shift+. or Shift+Numpad 2). The filter sits on top of both the MSAA and the UIA implementation of that property.

Comparing with and without the filter

The command "Toggles the removal of menu access keys that cannot be typed" in the "Menu access key filter" category of the Input gestures dialog has no default gesture. Assign one to switch between the original and the filtered behavior. The setting is not saved: the filter is on after every restart of NVDA.

Reporting test results

With the NVDA log level set to debug, every removed value is logged, for example:

Removed unusable access key(s) ['打'] from shortcut '打' of <Role.MENUITEM> named '打开...\tCtrl+O'

Please report the application, its language and the log line, especially if an access key you can actually type was removed or an unusable one is still read.

Requirements

NVDA 2026.1 or later.
